# 滞后资金费均值窗口验证计划

按已授权自动执行，使用 writing-plans / verification-before-completion 技能自查；不委派、不分支、不新增账户。

1. 在原有原生账本上只扩展 ETH 资金费特征窗口，L=[3,4,5]、N=[1,3,6]，F=0及其余参数冻结。N1已有结果只读，N3/N6共12新定义。合成测试先红后绿。
2. freeze.py保存完整spec及边界/门槛，所有新定义reserve后运行；run.py复用BTC完整净值并实际计算新ETH/父组合；audit.py独立Fraction/Decimal重建，验证来源、cost及全曲线NAV/回撤；完整两轴导出逐变体/逐折。
3. 使用原冻结观察器续接两个永续账户，独立L4窗口跨00funding及00:01日决策；仅适配只读审计的窗口和事件数。原SMA本轮不跨日，下轮必须原日切换分支。
4. 每个新配置finish，完成登记/来源/导出/监控检查。只提交轻量结果和必要原始证据，main非强制push后比对远端完整tree，再释放同一排他锁。

复核重点：窗口均值不能包含未可得00费率；N必须完整、最新不超16h；N1旧报告不改资格；原生单位/原始权重不缩放；跨日funding不能重复；零时长风险段不能计入；历史OOS重复开发局限必须披露。
